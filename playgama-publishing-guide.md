# Публикация игры на Playgama — рабочий справочник

> Файл-инструкция для ИИ-ассистента и для себя. Сверяться с ним ДО загрузки архива.
> Источники: [wiki.playgama.com](https://wiki.playgama.com/playgama/submitting-a-game.md),
> форма загрузки в [developer.playgama.com](https://developer.playgama.com/),
> и собственные грабли по игре «Кубоград» / Cubetown.
> Версия 1 — по итогам первой интеграции Bridge SDK v2.

---

## 0. Чем Playgama отличается от Яндекс Игр

Если уже проходил публикацию на Яндексе — вот что здесь **иначе**:

| | Яндекс Игры | Playgama |
|---|---|---|
| Хостинг | грузишь архив, играет с их CDN | так же: ZIP на серверы Playgama |
| SDK | Яндекс SDK | **Playgama Bridge** (обязателен, без него отказ) |
| Язык | русский основной | **английский основной**, каталог международный |
| Название | строго одно написание | своё на каждую заявленную локаль |
| Договор | ЕЛС/РСЯ блокирует отправку | договора до отправки не требуется |
| Дистрибуция | только Яндекс | Playgama **+ партнёрские порталы** (100+), можно исключать |
| Проверка | модерация | сначала **QA Tool** прямо в форме, потом модерация |

Главное следствие: **игра должна быть локализована**. Каталог международный, и
интерфейс обязан быть переведён на все языки, которые ты заявил в форме, — иначе
отказ (это прямым текстом в списке частых причин).

### 0.1. ⚠️ Про игры, сделанные нейросетями

Playgama прямо пишет в самопроверке, что **не принимает игры, полностью
сгенерированные ИИ без существенной ручной доработки визуала**. Их формулировка:
ИИ для сюжета, логики и игровой математики — нормально; игра, где вся графика
сгенерирована и не доведена руками, — отказ, потому что такие игры показывают
вдвое худшие метрики.

Практический вывод: **графика должна быть своей** — нарисованная кодом сцена,
собственная палитра, ручная композиция обложек. Сгенерированные нейросетью
картинки в качестве всего визуала — риск отказа.

## 1. САМОПРОВЕРКА ПЕРЕД ЗАГРУЗКОЙ

Список частых причин отказа с официальной страницы самопроверки. Пройти **до**
того, как собирать архив.

- [ ] **Bridge SDK интегрирован**, отправляется `game_ready`, прогресс пишется через `storage` SDK
- [ ] Интерфейс переведён на **все** заявленные языки, язык интерфейса совпадает с заявленным
- [ ] Реклама не рвёт геймплей, **глушит звук**, награда выдаётся честно
- [ ] Звук встаёт на паузу при рекламе и при сворачивании
- [ ] Прогресс сохраняется и восстанавливается
- [ ] Нет технических сообщений, ошибок, зависаний и падений
- [ ] Название в игре совпадает с названием в заявке — **внутри одной локали**
- [ ] Элементы интерфейса не обрезаются границами игрового поля
- [ ] Нет чужих прав: имён, логотипов, музыки, персонажей чужих игр
- [ ] Игра не копирует другую игру из каталога
- [ ] **Нет встроенной аналитики** (Google Analytics / GA4 и подобное) — это отдельный пункт технических требований
- [ ] Визуал доведён руками, а не полностью сгенерирован (см. 0.1)

### 1.1. Технические требования, которые ловит QA

- [ ] Регистрация/авторизация во внешних сервисах для запуска **не нужна**
- [ ] Полноэкранный режим на мобильных
- [ ] Элементы не деформируются при смене ориентации и размера окна
- [ ] Прогресс переживает поворот экрана
- [ ] Управление жестами на мобильных, мышью/клавиатурой на десктопе
- [ ] **Нет системного плеера** ни в одном браузере (значит — Web Audio, никаких `<audio>`/`<video>`)
- [ ] Нет уведомления про WebGL при открытии
- [ ] **Нет браузерной прокрутки** (свой скролл внутри игры — можно)
- [ ] Тексты и элементы не наезжают друг на друга
- [ ] У всех всплывающих окон есть крестик или кнопка закрытия
- [ ] Игра не привязана к URL, с которого открыта (никаких проверок домена)
- [ ] Соотношение активного поля на десктопе не превышает 1:2
- [ ] Браузеры: Chrome, Firefox, Opera, Safari, Edge. Android 5+, iOS 9+

### 1.2. Выбор языка — требование UX, о котором забывают

Playgama требует, чтобы игрок **мог сменить язык, не зная текущего языка игры**:

- [ ] Путь к выбору языка понятен без текста (шестерёнка настроек, глобус)
- [ ] Языки подписаны **флагами или самоназваниями** (`English`, `Español`), а не кодами

> ⚠️ Наши кнопки `RU` / `EN` — это коды, а не самоназвания. Формально требование
> просит флаги или самоназвания. Пока замечаний не было, но если модерация
> придерётся — менять подписи на `Русский` / `English`.

## 2. АРХИВ

- [ ] Формат — **ZIP**
- [ ] В **корне** архива лежит `index.html` (не в подпапке!)
- [ ] Общий размер файлов внутри — **не больше 300 МБ**
- [ ] Имена файлов и папок — **только латиница**
- [ ] Внутри лежит `playgama-bridge-config.json` рядом с `index.html`
- [ ] Игра работает из архива без шага сборки (проверить: распаковать в чистую папку, поднять `python3 -m http.server`, открыть)

### 2.1. Имя файла архива — на него смотрят

Имя архива видит модератор. Оно не должно содержать:

- **рабочих названий веток и стадий**: `demo`, `testing`, `wip`, `draft`, `final2`
- **старого названия игры**, если оно менялось
- кириллицы

Годится: `cubetown-1.0.0.zip`. Не годится: `claude-demo-and-testing-кубоград.zip`.

### 2.2. Как собрать архив

```bash
# из корня репозитория, ничего лишнего внутрь
zip -r ../cubetown-1.0.0.zip . \
  -x '.git/*' '.github/*' 'tools/*' 'store/*' 'dist/*' \
     '*.md' '.gitignore' '.nojekyll'
# проверить, что index.html лежит в корне архива
unzip -l ../cubetown-1.0.0.zip | head
```

Исключать `tools/`, `store/`, `dist/` и `*.md` обязательно: это разработческие
файлы, в игре они не нужны и только раздувают архив.

## 3. ПОЛЯ ФОРМЫ ЗАГРУЗКИ

Открывается по кнопке **Add Game** в [кабинете разработчика](https://developer.playgama.com/).
Звёздочкой отмечены обязательные.

| Поле | Что писать | Наш ответ |
|---|---|---|
| **Title\*** | Название в каталоге и в поиске. Короткое, 2–4 слова, **обязано совпадать с названием внутри игры** | `Cubetown` |
| **Game Engine\*** | Движок | `Plain JS` (никакого движка нет — чистые ES-модули и Canvas) |
| **Game Archive\*** | ZIP, `index.html` в корне, ≤ 300 МБ | см. раздел 2 |
| **Description\*** | Краткое описание: суть, жанр, чем игра своеобразна | см. 3.1 |
| **How to play\*** | Инструкция для игрока: правила, управление, цель | см. 3.1 |
| **Supported Devices\*** | Устройства и браузеры. **Используется для фильтрации каталога**: если отметить только iOS, игроки на Android игру не увидят | Desktop + Mobile (iOS и Android) |
| **Screen Orientation** | Поддерживаемая ориентация на мобильных. В противоположной покажут заглушку «поверни устройство» | `Portrait` |
| **Game Features** | Отметить всё, что в игре есть — это и есть «анкета», см. раздел 4 | см. раздел 4 |
| **Game Languages\*** | Все языки, которые поддерживает игра. **Каждый заявленный язык обязан быть переведён полностью** | `English`, `Russian` |
| **Media** | Скриншоты, обложки, иконки, видео. Формально необязательно, но каталог без них выглядит мёртвым | см. раздел 5 |
| **Distribution\*** | Кроме Playgama игра уходит на партнёрские порталы. Если куда-то не надо — отметить в списке исключений | оставляем все, сверившись с platform-specific requirements |
| **Link** | Ссылка, если игра уже опубликована где-то ещё | ссылка на Яндекс Игры, если игра там уже вышла |

### 3.1. Description и How to play — плейсхолдеры надо стирать

⚠️ **Главная глупая ошибка.** В полях `Description` и `How to play` форма
показывает пример-плейсхолдер с текстом про чужую игру. Он выглядит как
подсказка, но при отправке уезжает как твой текст, если его не заменить.

**Проверить перед отправкой: в каждом текстовом поле твой собственный текст, а
не пример из формы.** Модерация читает описания, и чужой текст — гарантированный
возврат.

Описание пишется **по-английски** (каталог международный) и не должно
противоречить содержимому игры.

Заготовка для «Кубоград»/Cubetown:

```
Description:
Cubetown is a calm sorting puzzle. Stack coloured cubes onto posts until each
post holds a single colour. Every solved level adds a new building to your city,
so the skyline grows as you play. Three difficulty modes, sixty handmade levels
each, no timers and no fail state.

How to play:
Tap a post to pick up the top group of cubes of the same colour, then tap another
post to put them down. A group only fits on an empty post or on top of the same
colour. Fill a post with one colour to lock it with a cap and earn a building for
your city. Undo, hint and an extra post are available if you get stuck.
```

## 4. GAME FEATURES — анкета и наши ответы

Это чекбоксы в форме. Отвечать честно: модерация проверяет заявленное.

| Пункт | Ответ | Почему |
|---|---|---|
| **Interstitial Ads** | **Yes** | Показываем между уровнями, не чаще раза в 3 минуты и не раньше 3-го уровня |
| **Rewarded Ads** | **Yes** | Только по явному нажатию: «Отменить» сверх бесплатных, «Подсказка», «+1 столбик» |
| **SDK authorization** | **No** | Авторизация игрока не используется, прогресс кладём в `storage` без привязки к аккаунту |

Если отметить `Interstitial Ads: Yes`, а рекламу не показывать — это расхождение
заявки и игры, повод к возврату. Обратное тоже верно.

## 5. ОБЛОЖКИ И МЕДИА

### 5.1. Размеры

| Формат | Размер | Где виден |
|---|---|---|
| Square 1:1 | **800×800** | плитка каталога |
| Portrait 9:16 | **1080×1920** | мобильные подборки |
| Landscape 16:9 | **1920×1080** | широкие баннеры и партнёрские порталы |

Допустимые форматы файлов: **mpeg / jpeg / png**. Для статичных обложек — PNG.

### 5.2. Требования к содержанию

- [ ] **Узнаваемый геймплей**: реальные объекты игры, а не абстракция и не арт «по мотивам»
- [ ] **Название латиницей**, крупно
- [ ] **Читается в превью 200 px** — именно так обложку видно в каталоге
- [ ] **Нет кнопок Play** и любых призывов к действию
- [ ] **Нет интерфейса игры**: кнопок, счётчиков, HUD
- [ ] **Нет мелкого текста** — в превью он превратится в грязь
- [ ] Композиция своя под каждый формат, а не одна картинка, обрезанная тремя способами

### 5.3. Проверка читаемости — обязательная

Уменьши обложку до 200 px по длинной стороне и посмотри. Ориентир по высоте букв
названия в таком превью:

| Формат | Высота букв при 200 px | Вывод |
|---|---|---|
| 800×800 | ≥ 15 px | с запасом |
| 1080×1920 | ≥ 10 px | нормально |
| 1920×1080 | ≥ 8 px | минимум, ниже — нечитаемо |

⚠️ **16:9 — самый опасный формат.** Название сбоку на узкой полосе превращается в
нечитаемую строчку. Полоса под название должна занимать **не меньше 40% ширины
кадра**, иначе в каталоге игрок не прочитает имя игры.

### 5.4. Как мы их делаем

`tools/store-assets.html` рисует все три обложки **настоящим рендерером игры**
(`src/render/scene.js`), поэтому стиль совпадает с игрой буквально. Там же панель
предпросмотра в 200 px и кнопки сохранения PNG.

Открывать **через локальный сервер**, не двойным кликом: рендерер подключается
ES-модулями.

```bash
python3 -m http.server
# http://localhost:8000/tools/store-assets.html
```

### 5.5. Обложки не требуют перезаливки билда

**Медиа сохраняются кнопкой Save отдельно от архива.** Если надо поменять только
обложку или описание — правишь поля, жмёшь Save, архив не трогаешь и билд не
перезаливаешь. Это экономит цикл модерации.

## 6. ИНТЕГРАЦИЯ BRIDGE SDK

Актуальная версия — **Bridge SDK v2**. Документация: [wiki.playgama.com/playgama/bridge-sdk](https://wiki.playgama.com/playgama/bridge-sdk/getting-started.md).

### 6.1. Подключение

```html
<!-- в <head>, НЕ async и НЕ defer:
     window.bridge должен существовать к запуску игрового модуля -->
<script src="https://bridge.playgama.com/v2/stable/playgama-bridge.js"></script>
```

Рядом с `index.html` — `playgama-bridge-config.json`. Без него SDK пишет в консоль
`Failed to load the bridge config file`, а консоль обязана быть чистой.

```json
{
  "advertisement": {
    "minimumDelayBetweenInterstitial": 180,
    "interstitial": {
      "placements": [
        { "id": "level_completed" }
      ]
    }
  }
}
```

Блок `platforms` заполняется идентификаторами конкретных площадок (`gameId`,
`appId` и т.п.) — их выдаёт кабинет при заведении игры. Редактор конфига:
[playgama.github.io/bridge-config-editor](https://playgama.github.io/bridge-config-editor/).

### 6.2. Инициализация

```js
await bridge.initialize();
// только теперь доступны bridge.platform, bridge.storage, bridge.advertisement
```

**До `initialize()` модули моста недоступны** — `bridge.platform` вернёт
`undefined` и SDK напишет ошибку в консоль.

### 6.3. Язык

```js
const lang = bridge.platform.language; // ISO 639-1: 'en', 'ru'
```

Если площадка язык не назвала, SDK сам подставляет язык браузера.

### 6.4. Сохранения — принимают МАССИВЫ

Самая частая ошибка при интеграции. Сигнатуры именно такие:

```js
// запись: два массива — ключи и значения
await bridge.storage.set(['save'], [data]);

// чтение: массив ключей → массив значений, null за отсутствующий ключ
const rows = await bridge.storage.get(['save']);
const data = rows[0];

// удаление
await bridge.storage.delete(['save']);
```

`storage.get('save')` со строкой **не работает** — облачные сохранения молча
не поедут.

Документация требует не писать прогресс в `localStorage` мимо `storage`.
Локальное зеркало допустимо только как страховка (см. 7.5).

### 6.5. Реклама — события через константы

```js
const ads = bridge.advertisement;

// интерстишл
const name = bridge.EVENT_NAME.INTERSTITIAL_STATE_CHANGED;
const handler = (state) => {
  if (state !== 'closed' && state !== 'failed') return;
  ads.off(name, handler);
  resolve(state === 'closed');
};
ads.on(name, handler);
ads.showInterstitial();          // placement необязателен
```

Состояния интерстишла: `loading` / `opened` / `closed` / `failed`.
Состояния rewarded: `loading` / `opened` / `closed` / **`rewarded`** / `failed`.

> ⚠️ **Награду выдавать только по состоянию `rewarded`.** На `closed` игрок получит
> её, не досмотрев ролик.

Требование рекламы: **при полноэкранной рекламе звук и геймплей ставятся на паузу.**

### 6.6. Сообщения площадке

```js
bridge.platform.sendMessage(bridge.PLATFORM_MESSAGE.GAME_READY);
bridge.platform.sendMessage(bridge.PLATFORM_MESSAGE.LEVEL_STARTED,   { world: 'easy', level: '3' });
bridge.platform.sendMessage(bridge.PLATFORM_MESSAGE.LEVEL_COMPLETED, { world: 'easy', level: '3' });
bridge.platform.sendMessage(bridge.PLATFORM_MESSAGE.LEVEL_PAUSED,    { world: 'easy', level: '3' });
```

Документированный список: `game_ready`, `in_game_loading_started/stopped`,
`player_got_achievement`, `level_started`, `level_completed`, `level_failed`,
`level_paused`, `level_resumed`. Параметры `world` и `level` необязательные.

Правильный порядок за уровень: **`level_started` → `level_completed`**, без
`level_paused` между ними при обычной победе. Паузу геймплея не отправлять на
загрузке и после победы — уровень уже закрыт своим сообщением.

> В рантайме SDK есть ещё `gameplay_started` / `gameplay_stopped`, но в таблице
> сообщений документации v2 их нет — похоже, наследие v1. Использовать
> документированные имена.

### 6.7. Обязательные isAudioEnabled и PAUSE_STATE_CHANGED

Оба помечены в документации как **Required**. Без них — замечание модерации
(«звук не встаёт на паузу при сворачивании» — прямо в списке частых отказов).

```js
// звук: площадка вправе потребовать тишины
if (bridge.platform.isAudioEnabled === false) muteAll();
bridge.platform.on(bridge.EVENT_NAME.AUDIO_STATE_CHANGED, (enabled) => {
  platformAudio = enabled !== false;
  applyMute();   // учитывает И настройку игрока, И запрет площадки
});

// пауза: останавливать цикл, таймеры и звук
bridge.platform.on(bridge.EVENT_NAME.PAUSE_STATE_CHANGED, (paused) => {
  setPauseReason('platform', paused === true);
});
```

**Паузу нельзя держать одним булевым флагом.** Причин минимум четыре: фон вкладки
(`visibilitychange`), потеря фокуса окна (`blur`/`focus`), событие площадки,
`postMessage` от хоста. Игра стоит, пока держится **хотя бы одна**:

```js
const pauseReasons = { hidden: false, blur: false, platform: false, host: false };
function setPauseReason(reason, active) {
  pauseReasons[reason] = active;
  const paused = Object.keys(pauseReasons).some((key) => pauseReasons[key]);
  ...
}
```

Иначе площадка снимет паузу у свёрнутой вкладки, и игра поедет в фоне.

**И ограничить дельту первого кадра после возобновления** — иначе твины прыгнут
вперёд на весь простой:

```js
const dt = skipDelta ? 0 : Math.min(MAX_DELTA, now - lastTime || 0);
skipDelta = false;
```

## 7. ГРАБЛИ, НА КОТОРЫЕ МЫ УЖЕ НАСТУПИЛИ

### 7.1. Не трогать `bridge.platform` до `initialize()`

```js
// ❌ так было — и на каждой загрузке в консоль летела ошибка SDK
if (window.bridge && window.bridge.platform) usePlaygama();

// ✅ признак моста — только метод initialize
if (window.bridge && typeof window.bridge.initialize === 'function') usePlaygama();
```

`bridge.platform` до инициализации возвращает `undefined` **и печатает
`Before using the SDK you must initialize it`**. Консоль с ошибками — повод к
замечанию, а само условие никогда не срабатывает: адаптер площадки не выбирается.

### 7.2. mock-платформа обязана откатываться на заглушку

Скрипт моста создаёт `window.bridge` **везде**, включая localhost и GitHub Pages.
В неподдерживаемом окружении `bridge.platform.id === 'mock'`.

```js
await adapter.init();
// мост поднялся, но площадки за ним нет — играем как без SDK
if (adapter.isMock && adapter.isMock()) adapter = createNoneAdapter();
```

Без этого локальная разработка и превью на Pages будут думать, что они на
площадке: сохранения уедут в mock-хранилище, реклама будет «показываться».

### 7.3. `language()` не должен возвращать жёсткий `'ru'`

```js
// ❌ заглушка выдавала свой язык за язык площадки
language() { return 'ru'; }

// ✅ пусто = «площадка языка не назвала», решает i18n
language() { return ''; }
```

Приоритет языка: **сохранённый выбор игрока → язык площадки → `navigator.language`
→ `en`**. Жёсткий `'ru'` в заглушке стоит выше `navigator` и ломает автоопределение:
английский браузер получал русский интерфейс.

Отдельно: **язык площадки не сохранять в `localStorage`** — иначе то, что портал
отдал в первый заход, залипнет навсегда.

### 7.4. Таймаут на инициализацию

Мост может загрузиться и не подняться. Без таймаута экран загрузки висит вечно.

```js
await withTimeout(adapter.init(), 5000);   // не поднялся — уходим на заглушку
```

### 7.5. Откат прогресса после сессии без моста

Сценарий: мост не успел за таймаут → играли на заглушке → прогресс лёг в
`localStorage` → в следующий заход мост поднялся → читаем облако, а там состояние
**до** той сессии. Прогресс откатился.

Лечение: фасад штампует каждое сохранение временем, а адаптер при загрузке
выбирает свежее из облака и локального зеркала.

```js
export async function save(data) {
  return adapter.save({ ...data, savedAt: Date.now() });
}

async load() {
  const cloud = await readCloud();
  const local = readLocal();
  if (!cloud) return local;
  if (!local) return cloud;
  // при равенстве и у старых сейвов без штампа выигрывает облако
  return stampOf(local) > stampOf(cloud) ? local : cloud;
}
```

Ключ локального зеркала должен **совпадать у всех адаптеров** — иначе сессия без
моста запишет прогресс туда, куда адаптер площадки не заглянет.

### 7.6. Мигание языка на загрузке

Мост асинхронный, а разметка статична. Если в HTML лежит русское название, а язык
окажется английским — логотип мигнёт с одного на другое до первого кадра.

Лечение: скрывать логотип сплэша, пока язык не определён, и показывать его в той
же функции, которая проставляет `lang`, `<title>` и `apple-mobile-web-app-title`.

### 7.7. Плейсхолдеры формы — чужой текст

См. 3.1. Проверять каждое текстовое поле перед отправкой.

### 7.8. Имя архива

См. 2.1. `demo`, `testing` и старое название игры в имени файла — это то, что
модератор увидит первым.

### 7.9. Латинский сабсет шрифта

Если шрифт подключён только кириллическим сабсетом, английское название на
обложках и в интерфейсе отрисуется **системным шрифтом**, и стиль поедет.
Проверить, что `unicode-range` латинского сабсета подключён.

## 10. ПАМЯТКА: частые причины отказа

1. Bridge SDK не интегрирован, нет `game_ready`, прогресс мимо `storage`
2. Игра целиком сгенерирована ИИ без ручной доработки визуала
3. Интерфейс переведён не на все заявленные языки
4. Реклама рвёт геймплей, не глушит звук или не выдаёт награду
5. Звук не встаёт на паузу при рекламе и при сворачивании
6. Прогресс не сохраняется
7. Технические сообщения, ошибки, падения, зависания
8. Название в игре не совпадает с названием в заявке
9. Элементы интерфейса обрезаны границами поля
10. Чужие права: имена, логотипы, музыка, персонажи чужих игр
11. Игра копирует другую игру из каталога
12. Встроенная аналитика (GA4 и подобное)

## 11. ЧТО ПРОВЕРИТЬ В КОДЕ НОВОЙ ИГРЫ (быстрый аудит)

```bash
# мост подключён и конфиг на месте
grep -n "playgama-bridge.js" index.html
ls playgama-bridge-config.json

# storage вызывается массивами
grep -n "storage\.\(get\|set\|delete\)" src/platform/playgama.js

# события берутся из констант, а не из строк
grep -n "EVENT_NAME\|PLATFORM_MESSAGE" src/platform/playgama.js

# обязательные подписки на месте (в адаптере площадки; игра обычно
# подписывается через фасад — ищи onAudioState / onPauseState)
grep -rn "AUDIO_STATE_CHANGED\|PAUSE_STATE_CHANGED" src/
grep -rn "onAudioState\|onPauseState" src/

# детект не трогает platform до initialize
grep -n "window.bridge" src/platform/sdk.js

# все обращения к localStorage в try/catch
grep -n "localStorage" src/ -r

# нет внешних запросов, кроме SDK площадок
# (для игры, которая выходит и на Яндексе, вторым допустимым хитом
#  будет yandex.ru/games/sdk — всё остальное лишнее)
grep -rn "https://" index.html style.css src/ | grep -v bridge.playgama.com
```

Все пункты должны сойтись **до** сборки архива.
