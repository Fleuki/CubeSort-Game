# CLAUDE.md

Головоломка-сортировка кубиков для Яндекс Игр и Playgama.
Полное описание механики, арта и таймингов — в `cubesort-design-doc.md`.
Требования площадки — в `yandex-games-publishing-guide.md`.
**Читай оба перед изменением кода.** Не выдумывай правила и цвета — они там записаны.

---

## Жёсткие правила

Нарушение любого из них — повод остановиться и спросить, а не «сделать по-своему».

1. **Ноль зависимостей.** Нет npm, нет бандлера, нет фреймворка, нет TypeScript.
   Чистый JavaScript, ES-модули, нативный `import`. Никаких CDN в рантайме.
2. **Игра запускается любым статическим сервером без шага сборки.**
   `python3 -m http.server` в корне — и всё работает. Бандлера нет.
   `tools/build-single.js` собирает `dist/game.html` для просмотра двойным
   кликом — это режим предпросмотра, не продакшен-путь.
3. **Один Canvas.** Всё игровое поле рисуется кодом. Никаких спрайт-листов,
   PNG-ассетов и SVG-иконок в игровой сцене. HUD — обычный DOM поверх канваса.
4. **Логика не знает о рендере.** Модули в `src/game/` не обращаются к
   `document`, `window`, `canvas`, `Audio`. Они принимают состояние и
   возвращают новое. Это позволяет прогонять их в Node без браузера.
5. **Рендер не мутирует состояние.** `src/render/` только читает.
6. **Локализация ru/en.** Русский — основной язык, английский нужен
   зарубежным площадкам Playgama. Язык при старте определяется сам:
   выбор игрока → язык площадки → язык браузера → `en`. Все строки живут
   в `src/i18n.js`, в разметке и коде их быть не должно — только ключи
   и вызовы `t()`. Третий язык не заводи без просьбы.
7. **Никаких внешних запросов, кроме SDK площадки публикации.**
   Единственное исключение — скрипт SDK той площадки, где игра выходит
   (Playgama Bridge, Яндекс SDK). Все ассеты остаются локальными: шрифты —
   woff2 в `assets/fonts/`, звук — CC0-семплы в `assets/audio/` через
   Web Audio API, переводы — внутри бандла. CDN для библиотек по-прежнему
   запрещены. Элементов `<audio>` и `<video>` нет: площадки заворачивают
   за системный плеер в шторке уведомлений. Часть эффектов остаётся
   процедурным синтезом — `playPlace()` строит комбо по пентатонике, и
   семплами это не собрать. Источники семплов записываются
   в `assets/audio/CREDITS.md`.
8. **Не трогай чужой трек.** Если задача про анимации — не переписывай
   генератор уровней «заодно».

## Структура

```
index.html
style.css
assets/fonts/          локальные woff2 (Unbounded, Onest), сабсет кириллицы
assets/audio/sfx/      CC0-семплы эффектов, wav
assets/audio/music/    фоновый трек, mp3
assets/audio/CREDITS.md источники и лицензии семплов
levels/levels.json     60 предгенерированных уровней
tools/gen-levels.js    офлайн-скрипт генерации, запускается в Node вручную
src/
  i18n.js              словари ru/en, t(), выбор и смена языка
  main.js              точка входа, игровой цикл, склейка модулей
  game/
    state.js           создание и клонирование состояния уровня
    rules.js           canMove, applyMove, isSolved, takeTopGroup
    generator.js       обратная генерация уровня
    solver.js          BFS для подсказки, с нормализацией состояния
    history.js         undo-стек
  render/
    iso.js             проекция, отрисовка кубика, штыря, подставки, теней
    scene.js           отрисовка кадра целиком
    city.js            макет города на фоне
    layout.js          расчёт позиций под размер экрана
  anim/
    tween.js           твин-движок и функции easing
    fx.js              частицы, тряска камеры
  audio/
    sfx.js             загрузка семплов, две шины громкости, музыка
  ui/
    hud.js             DOM-оверлей: кнопки, счётчики
    screens.js         загрузка, главный, победа, настройки
  platform/
    sdk.js             фасад: init, showAd, showRewarded, save, load, ready
    yandex.js          реализация под Яндекс SDK
    playgama.js        реализация под Playgama Bridge
    none.js            заглушка для локальной разработки
```

Новые файлы создавай внутри этой структуры. Не заводи `utils/` —
это свалка. Если функции некуда положить, значит структура требует
обсуждения, а не нового каталога.

## Код

- Отступ 2 пробела, точка с запятой, одинарные кавычки.
- `const` по умолчанию, `let` когда нужно, `var` никогда.
- Именование: `camelCase` для функций и переменных, `SCREAMING_SNAKE` для
  констант, `PascalCase` только для классов.
- Комментарии — по-русски, и только там, где неочевидно **почему**.
  Не комментируй, **что** делает строка.
- Магические числа выносим в именованные константы в начале файла.
  Все тайминги из раздела 6 дизайн-дока — константы, а не литералы.
- Никаких `class` ради `class`. Простые функции и объекты, если нет
  явной причины для класса (твин, частица — причина есть).

## Игровой цикл

Один `requestAnimationFrame`. Внутри:

```
дельта времени → обновить твины → обновить частицы → отрисовать кадр
```

Дельту ограничиваем сверху 50 мс, иначе после сворачивания вкладки
всё улетает. Первый кадр после паузы идёт с нулевой дельтой. Логика ходов
не в цикле — она вызывается из обработчика ввода.

Пауза набирается из причин (`pauseReasons` в `main.js`): фон вкладки,
потеря фокуса, событие площадки, `postMessage` хоста. Игра стоит, пока
держится хотя бы одна. Не заменяй это одним булевым флагом — площадка
снимет паузу у свёрнутой вкладки, и игра поедет в фоне.

## Производительность

Цель — 60 fps на бюджетном Android. Правила:

- Не создавать объекты в цикле отрисовки. Массивы частиц и твинов —
  переиспользуемые пулы.
- Canvas в devicePixelRatio, но не выше 2 — на 3x бюджетные телефоны тонут.
- Не вызывать `ctx.save()/restore()` на каждый кубик, если можно без них.
- Макет города перерисовывать не каждый кадр, а в отдельный offscreen-canvas
  и обновлять только при изменении.

## Ввод

Только `pointerdown`. Не мешай `touchstart` и `mousedown` — будет двойное
срабатывание. Обязательно `touch-action: none` на канвасе.
Хитбокс столбика — прямоугольник шире визуального штыря на 20% с каждой стороны,
пальцу нужен запас.

## Чего не делать

- Не подключать физический движок. Физики в игре нет.
- Не добавлять лидерборды, магазин, ежедневки, второй режим — это после релиза.
- Не писать солвер, который вызывается на каждый ход. BFS только по кнопке
  подсказки, с потолком по глубине.
- Не хранить прогресс только в `localStorage` — писать через фасад
  `platform/sdk.js`, чтобы работало и облако Яндекса.
- Не показывать рекламу во время анимации или сразу после проигрыша.
- Не рефакторить работающий модуль без просьбы.

## Проверка перед тем, как сказать «готово»

1. `node tools/gen-levels.js --check 1000` — все уровни решаемы.
2. Игра открывается локально без сервера и без ошибок в консоли.
3. Прогон уровня целиком: взять, положить, отменить, собрать столбик,
   пройти уровень — без визуальных рывков.
4. Сужение окна до 320 px по ширине — вёрстка не ломается.
5. Контекстное меню и выделение текста отключены, зум по двойному тапу не срабатывает.
6. В консоли нет предупреждений о внешних запросах.

Скриншот или запись экрана прикладывай к отчёту, если среда позволяет.
Словам «работает» без проверки веры нет.
